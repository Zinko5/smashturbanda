## [26.08.01.04] - Miniparche de Desarrollo

### 1. Nuevas características o funciones
* **Soporte de API Key Segura para TURN**: El intento de usar el Open Relay estático de Metered.ca fue revertido porque el servicio rechaza conexiones públicas, fallando silenciosamente. En su lugar, se implementó una constante `TURN_BACKEND_URL` en `multiplayer.js`. Esto permite al desarrollador usar un proxy serverless (como Cloudflare Workers) que oculta la API Key de Metered y distribuye credenciales dinámicas de TURN a los jugadores de forma invisible y segura.
* **Limpieza de UI de TURN**: Se removió el campo de API Key del menú Opciones, dejando solo la configuración avanzada de TURN personalizado para usuarios con servidores propios.

### 2. Correcciones de bugs antiguos
* **Conexión WebRTC Fallida (ICE Failed) entre Redes Distintas**: Resuelto el fallo de conexión entre dispositivos en redes diferentes (ej. WiFi ↔ datos móviles) que fallaban con error `ICE failed` al no existir servidores TURN de respaldo. La causa raíz era que en el parche `26.07.06.12` se habían eliminado los servidores TURN por problemas de formato de URLs, dejando el juego sin capacidad de relevo.

## [26.08.01.06] - Miniparche de Desarrollo

### 1. Nuevas características o funciones
* **Proxy de Cloudflare Definitivo**: Se reestructuró el Worker de Cloudflare para utilizar directamente una `API Key` permanente mediante una petición `GET` a Metered.ca. Esto evita por completo los bloqueos por límite de peticiones (Rate Limit 429/500) que ocurrían al generar múltiples contraseñas temporales mediante `POST` durante las pruebas de recarga de página.
* **Fallback a OpenRelay**: Se re-inyectó el servidor gratuito `openrelay.metered.ca` como última línea de defensa en el array de `iceServers`.

### 2. Correcciones de bugs antiguos
* **Diagnóstico de Bloqueo de Red (ISP)**: Se documentó exhaustivamente que el estado infinito de "conectando..." (ICE Failed silencioso) al jugar entre celular (datos móviles) y laptop no es un bug del código WebRTC ni de PeerJS. Las pruebas revelaron que la conexión fracasa también estando ambos dispositivos en la misma red Wi-Fi si el router tiene habilitado "AP Isolation" (Aislamiento de Clientes), o si el proveedor de telefonía móvil bloquea el protocolo UDP y WebRTC mediante Deep Packet Inspection (DPI) (ej. Telcel, Movistar, Claro) para impedir llamadas VoIP gratuitas. Ante estas redes hostiles (Symmetric NAT con bloqueo DPI), el estándar WebRTC P2P es bloqueado físicamente. **Solución:** Jugar en redes Wi-Fi residenciales estándar sin restricciones, o utilizar una VPN en el dispositivo móvil para evadir el bloqueo de la operadora.

### 3. Correcciones de bugs que vinieron con las nuevas características
* **Procesamiento de ICE Servers**: El parsing del JSON devuelto por Metered en `multiplayer.js` se refinó para extraer de manera limpia todas las URLs proporcionadas (UDP, TCP, TLS en los puertos 80, 443, 3478) manteniendo la última credencial activa, aumentando dramáticamente la resiliencia en redes que no bloquean P2P pero que sí filtran puertos estándar.
